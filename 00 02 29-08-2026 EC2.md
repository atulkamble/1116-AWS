# Linux Fundamentals + AWS EC2 Practical Notes

## 1. What is Linux?

**Linux** is a free and open-source operating system family based on the **Linux kernel**.

Linux is widely used for:

* Servers
* Cloud computing
* DevOps
* Containers
* Kubernetes
* Web hosting
* Databases
* Networking
* Embedded systems
* Supercomputers

### Linux History

**UNIX → Linux**

**UNIX** is an older operating system family that influenced the design of Linux.

**Linus Torvalds** started developing the Linux kernel in **1991**.

### Kernel

The **kernel** is the core component of an operating system.

```text
User
  ↓
Applications
  ↓
Shell
  ↓
Kernel
  ↓
Hardware
```

The kernel manages:

* CPU
* Memory
* Processes
* Devices
* File systems
* Networking

# 10. Hypervisor

A **hypervisor** creates and manages virtual machines.

Two common categories:

### Type 1 — Bare-Metal Hypervisor

Runs directly on physical hardware.

```text
Hardware
   ↓
Hypervisor
   ↓
VM1   VM2   VM3
```

Examples include:

```text
VMware ESXi
Microsoft Hyper-V
Xen
KVM-based virtualization
```

### Type 2 — Hosted Hypervisor

Runs on top of a host operating system.

```text
Hardware
   ↓
Host OS
   ↓
Hypervisor
   ↓
Virtual Machine
```

Examples:

```text
Oracle VirtualBox
VMware Workstation
VMware Fusion
```

# 12. SSH

**SSH = Secure Shell**

Default port:

```text
22
```

SSH is commonly used for securely connecting to remote Linux servers.

Architecture:

```text
Your Computer
     |
     | SSH : 22
     ↓
AWS Security Group
     |
     ↓
EC2 Linux Server
```

Example:

```bash
ssh -i "key.pem" ec2-user@SERVER
```

---

# 13. PEM and PPK Keys

## `.pem`

A `.pem` private key file is commonly used with OpenSSH when connecting to AWS EC2 Linux instances.

Example:

```bash
ssh -i "key.pem" ec2-user@SERVER
```

## `.ppk`

`.ppk` means **PuTTY Private Key**.

It is traditionally used by **PuTTY** on Windows.

```text
Windows
   ↓
PuTTY
   ↓
.ppk
   ↓
Linux Server
```

Modern Windows systems can also use OpenSSH directly with `.pem` keys, so PuTTY/`.ppk` is not mandatory.

# 16. Security Group

Configure inbound rules as required:

| Type  | Protocol | Port |
| ----- | -------- | ---: |
| SSH   | TCP      |   22 |
| HTTP  | TCP      |   80 |
| HTTPS | TCP      |  443 |

For SSH practice, restrict port `22` to **your IP address** rather than exposing SSH to the entire internet.

Architecture:

```text
Internet
   |
   | SSH 22
   | HTTP 80
   | HTTPS 443
   ↓
Security Group
   ↓
EC2 Instance
   ↓
Amazon Linux
```

# 17. Connect to EC2

Navigate to the directory containing your key.

Example:

```bash
cd Downloads
```

Check:

```bash
ls
```

You should see:

```text
key.pem
```

On Linux/macOS/WSL, restrict the private key permissions:

```bash
chmod 400 key.pem
```

Connect:

```bash
ssh -i "key.pem" ec2-user@ec2-34-229-150-10.compute-1.amazonaws.com
```

> The hostname above is only an example from the lab. Use the **Public IPv4 DNS** of your current EC2 instance.

For Amazon Linux, the common default username is:

```text
ec2-user
```

# 32. Lab Cleanup

After completing the practice, clean up AWS resources you no longer need.

## Terminate EC2 Instance

```text
AWS Console
   ↓
EC2
   ↓
Instances
   ↓
Select server
   ↓
Instance state
   ↓
Terminate instance
```

Termination permanently removes the instance, so verify you no longer need its data first.

## Delete Key Pair from AWS

```text
EC2
 ↓
Key Pairs
 ↓
Select key
 ↓
Delete
```

Also securely delete the local private key if it will no longer be used:

```text
key.pem
```

## Delete Security Group

If you created a dedicated lab security group such as:

```text
launch-wizard-*
```

delete it after it is no longer associated with resources.

```text
EC2
 ↓
Security Groups
 ↓
Select lab Security Group
 ↓
Delete
```

> Do not delete the **default security group**. Only delete the dedicated security group created for the lab if it is no longer required.
